# SoC bring-up research

`devicetrees/` holds hardware inventories generated by the `DeviceTree survey` workflow
(`scripts/dt-survey.py`): every DeviceTree node of the newest IPSW per SoC, with its `compatible`
list and register blocks. They are the spec sheets new machine models are written against.

## What this means for bring-up order

The interrupt controller, IOMMU and IOP mailbox wrapper are what XNU touches first, and they come in
a few generations shared by many SoCs. Each generation modelled once unlocks every SoC that uses it.

| Step | SoCs | New hardware vs. what Inferno T8030 (A13) already models |
|---|---|---|
| 1 | A14 (T8101), M1 (T8103) | Same AIC v1 and DART t8020. New: `ascwrap-v4` IOP wrapper (ANS, SIO, SMC, AOP, SEP), PMGR/GPIO/display revisions |
| 2 | A15 (T8110), M2 (T8112) | AIC v2, DART t8110 (both documented by Asahi Linux for M1 Pro/Max/M2) |
| 3 | A16 (T8120) | `ascwrap-v6` IOP wrapper |
| 4 | A17 (T8130), A18 (T8140), M4 (T8132) | AIC v3; A18/M4 drop the classic GPIO node |
| 5 | A10–A12 (T8010, T8015, T8020) | Between Inferno's S8000 (A9) and T8030 (A13): older IOP (`iop,t80xx`), ANS2 on A11 |

The method for each step: boot the target IPSW on the closest existing machine with
`ipsw-emu boot --force-backend …` (Boot test workflow input `force_backend`), read the first panic,
model that block, repeat.
